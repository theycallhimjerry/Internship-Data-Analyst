1. Purpose of this Suite

This suite provides structured practice material for a Data Analyst internship focused on commercial analysis. Interns learn to query, clean and combine datasets with SQL and Python; run exploratory analysis and statistical validation; build stakeholder-ready views of customer behaviour, sales, revenue and operational KPIs; analyse churn, demand patterns and segments; and turn evidence into retention and growth recommendations. All activities are designed to be completed through shared digital workspaces and scheduled virtual reviews, without requiring physical presence in an office.

The materials include nineteen CSV datasets, nineteen XLSX workbooks, six Word guides, six PDF frameworks, six HTML phase pages, three presentation decks, supporting JSON catalogues and a simple workflow visual. Every document is written for its own topic. Body text is not reused across files.

2. Role Expectations

Interns are expected to operate as junior commercial analysts. That means:

  • Extracting and joining data with transparent SQL, and applying consistent Python cleaning rules for dates, amounts, keys and categories.
  • Profiling distributions, missingness and outliers before formal tests, and logging methods and assumptions so results can be reproduced.
  • Calculating and presenting KPIs that match the definitions in the KPI catalogue, with clear targets, status bands and data-quality indicators.
  • Investigating churn drivers, demand forecast error and segment differences, and ranking opportunities by impact and feasibility.
  • Writing recommendations in a fixed structure: observation, evidence, expected impact, action, owner and success measure.
  • Keeping source, method, assumption and KPI documentation complete enough that a supervisor can review the pack without a verbal walkthrough.

3. Programme Structure

Foundation — Source documentation, SQL extraction and joins, Python cleaning, reconciliation between systems, and quality profiles. Outputs: cleaned tables, query logs, source register entries, data notes.

Applied analysis — Exploratory analysis, statistical validation, behaviour and sales KPI construction, churn and demand diagnostics, segmentation profiles. Outputs: EDA summaries, test results, dashboard facts, opportunity register entries.

Integrated insights — Prioritised retention and growth recommendations, benefit tracking, final synthesis pack for virtual stakeholder review. Outputs: recommendation tracker, prioritisation matrix, final project pack with appendix of definitions and assumptions.

7. Recommended Working Sequence

  1. Read this README and the phase page that matches your current task.
  2. Open the relevant CSV and XLSX files and profile keys, nulls and categorical codes.
  3. Write and version SQL extraction and join scripts; apply Python cleaning rules; reconcile totals.
  4. Run EDA and any required statistical tests; log methods and assumptions.
  5. Calculate KPIs from catalogue definitions; build or update dashboard facts; note data-quality issues.
  6. Analyse churn, demand or segments as required; quantify commercial impact.
  7. Draft recommendations with owners and success measures; update trackers.
  8. Assemble the stakeholder pack; circulate before the virtual review; record decisions the same day.

8. Submission Checklist

  • Datasets cleaned, joined and validated with documented SQL and Python steps.
  • EDA and statistical validation recorded with assumptions and effect sizes where tests were used.
  • KPIs defined in the catalogue and calculated consistently across views.
  • Churn, demand and segment insights supported by named extracts and methods.
  • Recommendations structured with observation, evidence, impact, action, owner and success measure.
  • Sources, methods, assumptions and KPI definitions documented and versioned.
  • Pack is internally consistent and suitable for remote review without further verbal explanation.
Working practice: Prefer written logs and versioned scripts over informal verbal agreements. Update trackers on the same day as the work. When numbers differ between two outputs, reconcile before presenting either figure to stakeholders.
